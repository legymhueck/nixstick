# Repository Guide for Agents

Minimal NixOS desktop (MangoWM + Noctalia) on a USB stick that boots on any x86_64 UEFI PC and leaves no traces there (one configuration per stick in `hosts/<hostname>/`, the first is `nixstick`; user `m`): one root flake, shared `common/`, the desktop in `nixos-mango/`, scripts in `scripts/`, installer `install.sh`. README.md has the full layout.

## Start of every session

Booted from a stick (`hostname` is `nixstick*`), work through "Open tasks on the stick" below: say what is open, do on your own what needs no password and no decision (marked *auto*), ask before the rest. Remove an item in the same commit once it is done on every stick; the list travels with the repo because the stick has its own Claude memory. On the main system (`nixssd`, `x240`) only mention that the list is not empty.

## How it fits together

- `nixosConfigurations.<hostname>` exists for every `hosts/<hostname>/hardware-configuration.nix` (generated by `install.sh`, never edited or shared between sticks); the flake sets `networking.hostName` from it and adds the optional `hosts/<hostname>/host.nix`. `install.sh` refuses existing names. A pre-switch check in `common/base.nix` aborts activation if a disk of the configuration is missing. `vars.project` (`nixstick`) names the eval twin `nixstick-eval` (`/dev/null` stand-in: for checks only, never deploy).
- Module arguments `inputs` and `vars` (`common/vars.nix`) come from `specialArgs`/`extraSpecialArgs`; never `import` vars.nix in modules.
- `common/` = system + Home Manager base; `nixos-mango/` = desktop specifics.
- One `pkgs` everywhere (`useGlobalPkgs`). No overlay and no local packages: everything comes from nixpkgs and its binary cache.
- One spot for applications: free and unfree nixpkgs applications go into `common/apps.nix`; unfree ones also need a pname entry in the allowlist in `common/base.nix` (claude-code, github-copilot-cli, copilot-language-server, veracrypt, the Claude VSCodium extension). The browser itself is `programs.firefox` in `common/firefox.nix`; ungoogled-chromium in `apps.nix` exists only for the Claude browser agent. foot is the only terminal; the editors are VSCodium via `programs.vscodium` (never `programs.vscode` with `package = vscodium`: that writes to VS Code's paths, VSCodium would not see the extensions) and Neovim via `programs.neovim` in `common/neovim.nix` (plugins from nixpkgs, Lua config in `dotfiles/nvim/lua/m`, linked out of the store so edits apply without a rebuild).
- Theming: Noctalia generates the GTK/Qt files (`theme.templates` in `nixos-mango/desktop.nix`); zathura's colors come from the community template `zathura` (`~/.config/zathura/noctaliarc`, included by `programs.zathura` in `common/apps.nix`). `nixos-mango/home.nix` points both qt5ct and qt6ct at the generated `colors/noctalia.conf`; `QT_QPA_PLATFORMTHEME=qt6ct` (`nixos-mango/configuration.nix`) covers both toolkits because qt5ct's plugin also registers the `qt6ct` key. Double Commander from nixpkgs is the **Qt5** build, so it needs qt5ct — installing only qt6ct leaves it on the default light palette.
- No install stages: the installer sets up everything in one run.
- Foreign PCs (school PCs, in an emergency a teacher's PC) must not change and must not show that the stick booted: `common/traceless.nix` (no EFI variable writes, read-only efivarfs, no `systemd-boot-random-seed`/`systemd-pstore`, `efi_pstore` off, TPM2 units off, chrony without `rtcsync`/RTC trimming, no DHCP hostname, stable Wi-Fi MAC, SATA/NVMe hidden from udisks). `efi-traces` finds and removes traces of older versions.
- Login: password, fingerprint (own devices only) or YubiKey (`common/yubikey.nix`, `pam_u2f`, origin `pam://nixbox` and `common/u2f_keys` shared with the main repo). gnome-keyring is unlocked by the LUKS passphrase (`pam_fde_boot_pw`, `nixos-mango/configuration.nix`).
- Filen: `common/filen.nix` syncs `~/filen` two-way with the whole Filen drive (filen-cli, user unit `filen-sync`). The on/off switch is the flag file `~/.config/filen-cli/sync-enabled` (`filen-sync on|off`), not `systemctl --user enable`: Home Manager links the unit into `default.target` itself. Printable guide `docs/tips/filen.typ` (Typst on purpose, for printing) covers only the stick-specific part; setup, rules and troubleshooting are in the main repo nixos (`docs/setup/cloud-sync.typ`), not duplicated here. Never delete `~/filen` while the sync runs: a two-way sync can carry the deletion into the cloud (happened once on 2026-11-25, the cloud survived). `filen-sync off` first; a fresh start also removes `~/.config/filen-cli/sync/state` (the login stays). Progress: `filen-sync status` only shows that the unit runs (`--continuous --quiet`); compare `filen stat <dir>` with `du -sb --apparent-size`. `~/filen` is smaller than the cloud on purpose (`excludeDotFiles`, e.g. students' `.git`), and `filen statfs` also counts trash and old versions.
- Mail: `common/mail.nix` (aerc over IMAP directly, no Maildir to spare the flash; msmtp/msmtpq sends; passwords from `pass` with GPG, pinentry-qt so no curses prompt draws over aerc). One `mkAccount` block per address in `accounts.email.accounts` (first: `gymhueck`, `mail.nrw.schule`, primary); passwords are the pass entries `mail/<address>`. isync is installed, not set up. Printable tutorial `docs/tips/aerc.typ` (Typst, like the Filen guide).
- Updates: `update` = `lock-sync` (all inputs, then nixpkgs + Mango pinned to the main repo's `flake.lock`, so Mango comes from the Cachix cache `nixbox-m`).

## Invariants

- `system.stateVersion` (in `common/base.nix`) and `home.stateVersion` stay `26.05`.
- No `inputs.noctalia.inputs.nixpkgs.follows` (the Noctalia Cachix cache needs its own pin).
- Unfree packages only via the explicit allowlist in `common/base.nix` (names as `lib.getName` returns them); keep it explicit instead of `allowUnfree = true`.
- Mango login: LUKS passphrase = user password. greetd autologin (`initial_session`) at boot only, tuigreet afterwards. Never set an empty password; root stays locked.
- zram only, no swap file. `programs.nh` cleans; never also enable `nix.gc`.
- USB stick: everything in `common/traceless.nix` stays (never `canTouchEfiVariables`, never battery thresholds, `fwupd`, TPM use or an RTC write); `time.hardwareClockInLocalTime = true` (it boots almost only on Windows PCs whose clock cannot be changed); hardware support stays generic (`common/hardware-portable.nix`, no vendor-only services or `LIBVA_DRIVER_NAME`). Spare the flash: journal and `/tmp` in RAM, Firefox cache in RAM (`common/firefox.nix`), no snapper, no `nix.optimise.automatic`. The installer mounts the ESP by device, never by label.
- `programs.nix-ld` stays enabled (uv-managed Python and wheels for the repo unterricht); extend `programs.nix-ld.libraries` on top of its default, never replace it.
- Cursor: set once as `nixbox.cursor` in `nixos-mango/configuration.nix`; `desktop.nix` reads it via `osConfig` for dconf, Mango, `gtk.cursorTheme` and the `XCURSOR_*` session variables.
- `install.sh` copies the whole checkout and commits with `git add -A` (`.gitignore` covers `result*`).

## Workflows

```sh
nix flake check   # statix, deadnix, shellcheck + evaluation of all outputs
nix eval .#nixosConfigurations.nixstick-eval.config.system.build.toplevel.drvPath
nix eval .#nixosConfigurations.nixstick.config.system.build.toplevel.drvPath        # the real system
nix fmt           # nixfmt; CI fails on unformatted files
```

Flakes only see git-tracked files: `git add` new files before evaluating. Users rebuild with `nh os switch`.

## Making changes

- Printable docs (Typst cheat sheets, handouts) render into `out/` next to the source (`docs/tips/zathura.typ` -> `docs/tips/out/zathura.pdf`), the same rule as the main repo nixos and the repo unterricht; `out/` is git-ignored everywhere and never committed. Neovim `<leader>re` writes there, `<leader>ro` opens it.

- Shared things go in `common/`; the variant dir only holds desktop-specific things.
- New or renamed nix file: update the `imports`. `install.sh` needs no file list: before wiping it evaluates `nixstick-eval`, which fails on any missing file.
- Shell scripts (`install.sh`, `scripts/`): `shfmt -i 2 -ci`, checked by the flake check `lint`.
- New nixpkgs application (free or unfree): `common/apps.nix` — that is the single spot; allowlist entry in `common/base.nix` when unfree.
- No own packages (`pkgs/` was removed 2026-11-17). If one is ever needed, copy it from the main repo's `pkgs/` together with its overlay line, but only if it does not compile for long. Prefer wrapping a finished package (`symlinkJoin`) over `overrideAttrs`, which forces a local build.
- New script: `scripts/<name>.sh` plus a `mkScript` line with its runtime dependencies in `common/scripts.nix`.
- New user-facing command, alias or script: add it to `docs/tips/commands.md` and `scripts/README.md`.
- Anything that writes to hardware (firmware, EC, TPM, RTC, fingerprint reader, internal disks) needs a check against `common/traceless.nix` first.
- Firefox: `profiles.default.settings` plus `policies` in `common/firefox.nix`.

## Relation to the main repo

- GitHub `legymhueck/nixstick` (renamed from `nixos-minimal-mango` on 2026-11-17; the old URL redirects). Sister repo of the main repo **nixos** (GitHub `legymhueck/nixos`, the full system; hosts `nixssd`, an external SSD booted on the same laptop when it stays put, and `x240`). This one is the minimal variant for a USB stick: only cached packages, generic hardware, flash-friendly settings. Ideas are often ported from there; check the invariants above before copying (no snapper, no `nix.optimise`, no `canTouchEfiVariables`, no install stages, no local builds).
- Paths: `~/nixos` always means the config of the system that is running. On a stick it is this repo; the main repo, if cloned, lives elsewhere (here `~/GitHub/nixos_full/nixos`). Booted from `nixssd`, `~/nixos` is the main repo. In docs, name the repos (nixstick, the main repo nixos), never write `~/nixos` for the main repo.
- Differences on purpose: docs here are English Markdown (`docs/tips/`), not German Typst; applications live in one file (`common/apps.nix`), not in four stage lists; no `pkgs/`.
- Ported from the main repo on 2026-11-17: `shfmt` in the lint check, the evaluation preflight in `install.sh`, `actions/checkout` v7.0.1.
- Ported on 2026-11-21: `hosts/` + pre-switch disk check, YubiKey, gnome-keyring with `pam_fde_boot_pw`, udiskie service, nix-index-database + comma, Mango colors from Noctalia's template, Super+L, Bluetooth headset no-autoswitch, `tailscale --operator`, the `nixbox-m` cache.
